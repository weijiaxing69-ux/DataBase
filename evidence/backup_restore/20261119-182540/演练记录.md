# 维护模块备份与还原演练记录

- 演练时间：2026-11-19 18:25（本机时间）
- MySQL：8.0.29，`log_bin = ON`
- 源库：`charging_platform_test`（由 `scripts/rebuild_demo_db.py --with-emergency --yes` 重建）
- 目标库：`charging_platform_restore_drill`（演练结束后删除，避免占用演示环境）
- 备份文件：`dump.sql`（579062 字节，含表结构、数据、视图、存储过程、触发器与事件）

## 一、执行步骤

```bash
MYSQL_BIN="C:/Users/zhangxinhao/AppData/Local/Programs/MySQL/mysql-8.0.29-winx64/bin"
"$MYSQL_BIN/mysqldump.exe" --host=127.0.0.1 --user=root --protocol=TCP \
  --default-character-set=utf8mb4 --single-transaction \
  --routines --triggers --events \
  charging_platform_test > dump.sql

"$MYSQL_BIN/mysql.exe" --host=127.0.0.1 --user=root --protocol=TCP \
  -e "drop database if exists charging_platform_restore_drill;
      create database charging_platform_restore_drill
      character set utf8mb4 collate utf8mb4_0900_ai_ci;"

"$MYSQL_BIN/mysql.exe" --host=127.0.0.1 --user=root --protocol=TCP \
  --default-character-set=utf8mb4 charging_platform_restore_drill < dump.sql
```

## 三、结论

全量备份可以在隔离库中完整还原，表数据、视图、过程与触发器数量一致。演练采用 `mysqldump --single-transaction`，对 InnoDB 表不阻塞线上写入。

备份策略：每日一次全量备份，binlog 已开启，可按时间点做增量恢复；恢复目标（RPO）为最近一次全量备份后的 binlog 位点，恢复时长（RTO）按数据量与磁盘性能实测，本演练在 579 KB 数据上数秒完成。

边界说明：本次为演示库级别的单机演练，未覆盖跨机房与备份介质失效场景；演示数据可在答辩现场用 `scripts/rebuild_demo_db.py` 一键重建。
