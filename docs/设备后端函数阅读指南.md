# 设备后端函数阅读指南

代码位于 `backend/app/modules/assets/`，公共快照位于 `backend/app/shared/contracts.py`。
按 V1.4 的公开函数名、参数、字段和接口路径实现；数据库仍由统一建表脚本管理。

## 建议阅读顺序

1. `schemas.py`：前端可以传什么，返回什么，哪些值不合法。
2. `router.py`：网址、查询参数、请求体如何进入 Service。
3. `service.py`：权限、资源范围、业务检查、事务和返回值。
4. `dao.py`：SQL 查询、分页计数和加锁。
5. `tests/assets/test_device_lifecycle.py`：完整调用示例和失败场景。

## 业务函数清单

以下函数在 `service.py` 中。已有 CRUD 继续保留，并补充了设备业务校验。

| 函数 | 作用 |
| --- | --- |
| `list_piles(db, *, actor, query)` | 按授权场站范围筛选充电桩，然后分页并计数 |
| `get_pile(db, *, actor, pile_id)` | 查看充电桩详情 |
| `create_pile(db, *, actor, request)` | 新增默认草稿、离线的充电桩 |
| `update_pile(db, *, actor, pile_id, request)` | 更新桩档案，禁止把整桩功率降到已有单枪功率以下 |
| `list_guns(db, *, actor, query)` | 按授权范围查询枪列表 |
| `get_gun_detail(db, *, actor, gun_id)` | 供 HTTP 接口查看枪详情 |
| `create_gun(db, *, actor, request)` | 检查所属桩、功率、枪序号后新增枪 |
| `update_gun(db, *, actor, gun_id, request)` | 修改枪档案，检查单枪功率上限及退役状态 |
| `list_change_requests(db, *, actor, query)` | 查询变更申请列表 |
| `get_change_request(db, *, actor, request_id)` | 查询单条申请 |
| `create_change_request(db, *, actor, request)` | 运维工程师提交申请，保存原档案快照，暂不修改设备 |
| `review_change_request(db, *, actor, request_id, request)` | 管理员批准或驳回，禁止自批、重复审批、使用过期快照 |
| `list_acceptances(db, *, actor, query)` | 查询验收历史 |
| `get_acceptance(db, *, actor, acceptance_id)` | 查询一次验收结果 |
| `create_acceptance(db, *, actor, request)` | 新增验收记录，由四项测试计算通过与否，通过后更新生命周期 |
| `list_device_commands(db, *, actor, query)` | 查询设备启停命令列表 |
| `get_device_command(db, *, actor, command_id)` | 查询单条命令 |
| `list_device_status_logs(db, *, actor, query)` | 查询设备运行状态历史 |
| `get_device_status_log(db, *, actor, status_log_id)` | 查询单条状态历史 |
| `issue_device_credential(db, *, actor, pile_id, request)` | 管理员签发设备凭据，只存摘要，明文只在本次响应返回 |

Router 已包含上述业务对应的 HTTP 接口。新增申请、审批、验收、命令查询、状态历史和凭据签发共 12 个接口。

## 其他模块调用的设备函数

这些函数不直接提供 HTTP 路由。调用方先完成鉴权，并负责整个事务的提交或回滚。

| 函数 | 作用 |
| --- | --- |
| `get_gun(db, gun_id)` | 返回只读 `GunSnapshot`，包含当前充电订单编号 |
| `lock_gun(db, gun_id)` | 先锁所属桩，再锁枪，返回只读快照 |
| `change_gun_status(db, gun_id, *, expected_status, new_status, reason)` | 核对旧状态再修改并记录历史，不允许绕过恢复复核 |
| `claim_gun_for_order(db, *, gun_id, order_id)` | 核对当前充电订单归属后占枪 |
| `release_gun_for_order(db, *, gun_id, order_id, reason)` | 订单结束后释放枪，保留故障和离线事实 |
| `mark_pile_offline(db, *, pile_id, detected_at, reason)` | 持锁复核心跳超时，将桩和枪置离线，保留订单 |
| `touch_pile_heartbeat(db, *, pile_id, received_at)` | 接收较新的有效心跳，仅更新通信事实 |
| `recover_pile_status(db, *, pile_id, verified_at)` | 复核持续正常采样、告警恢复和工单闭环后恢复运行状态 |
| `enqueue_device_command(db, *, gun_id, order_id, command_type)` | 幂等创建启停命令及 Outbox 事件，事务内不发送网络请求 |

订单调用顺序是本实现的集成约定：先 `lock_gun`，在同一事务写入并 flush 当前 `charging` 订单，再调用 `claim_gun_for_order` 和 `enqueue_device_command`，最后由订单业务提交。结束订单时先更新订单状态，再释放枪。任何一步失败均回滚整个事务。

## 需要理解的规则

- `actor` 是服务端认证得到的当前账号；`query` 是列表查询条件；`request` 是新增或修改请求体。
- 生命周期与运行状态分开。验收通过让生命周期变为 `active`，不会直接把离线设备变为空闲。
- 变更审批与档案生效处于同一事务。迁移、改造后进入待验收，不能直接上线。
- 桩迁移的 `proposed_data` 使用 `{"station_id": 目标编号}`；枪迁移使用 `{"pile_id": 目标编号, "gun_no": 枪序号}`。这是本实现选择的 JSON 白名单，团队需要统一。
- 枪表没有独立的退役生命周期字段，因此本实现要求通过所属桩退役，避免增加文档之外的运行状态。
- 凭据明文不写入数据库；数据库只保存 SHA-256 摘要。
- 状态历史和验收历史通过新增记录保留；没有提供覆盖历史的更新接口。

## 联调边界

后续已按用户要求补入设备所需的成员4认证、`assert_resource_scope`、权限兼容映射和统一业务异常处理。当前 `assets.*` 细分权限及旧种子兼容映射为自定义约定，详见《设备与成员四联调说明》。

Router 原先无条件503阻断已替换。保留原有业务隔离测试，另外新增不替换身份和范围检查的真实登录HTTP联调测试；没有验证现有MySQL数据和真实设备网络。

订单、告警、采样、工单表正式实现仍由对应成员提供；演示入口提供最小模拟。命令及Outbox消费、租约和重试已由worker.py实现，demo.py提供模拟设备回执，真实协议适配器仍需替换。

## 测试

在 `backend` 目录运行：

```powershell
& '../.venv/Scripts/python.exe' -m unittest discover -s tests/assets -p 'test_*.py'
```

测试使用 SQLite 内存数据库，并禁止连接 MySQL；不修改现有数据库内容。SQLite 测试不验证 MySQL 的并发锁行为，真实跨成员联调仍需检查事务调用顺序。
