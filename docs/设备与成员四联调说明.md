# 设备与成员四联调说明

本次完成设备模块所需的成员4认证及授权实现，并增加独立演示入口。
演示数据全部在 SQLite 内存中，重启清空，不连接或修改现有 MySQL。
没有实现会员、车队、钱包等与本次设备联调无关的成员4完整业务。

## 启动

在项目根目录的 PowerShell 中执行：

```powershell
Set-Location backend
& '../.venv/Scripts/python.exe' -m uvicorn app.demo:create_app --factory --host 127.0.0.1 --port 8001
```

浏览器打开 `http://127.0.0.1:8001/docs`。停止时在终端按 Ctrl+C。
单进程演示即可，不加 `--workers`，每个进程都有自己的内存数据库。

## 在接口文档中操作

1. 调用 `POST /api/v1/auth/login`，提交账号密码，复制响应里的 `access_token`。
2. 点击接口文档右上角 Authorize，在 HTTPBearer 输入框中填写 token 原文。
3. 调用 `/api/v1/auth/me` 查看账号的角色和权限，再查询设备列表。
4. 用运维账号创建变更申请，再换管理员账号审批，查看桩详情确认新值生效。
5. 调用 `POST /api/v1/assets/acceptances`，验收桩1，四个测试字段全部传 `true`。
6. 调用 `POST /api/v1/assets/piles/1/credentials`，填写未来且带时区的过期时间。
7. 保存本次返回的 `secret_token`。改用设备 token 调用 `/api/v1/demo/heartbeat`。
8. 约35秒后再调用一次心跳，让观察窗口存在两条正常采样。换回管理员 token 调用 `/api/v1/demo/piles/1/recover`。
9. 调用 `/api/v1/demo/orders`，请求 `{"gun_id":1}`，模拟开始充电并占枪。
10. 调用 `/api/v1/demo/dispatch` 消费一条命令，查询命令详情应为 `succeeded`。
11. 调用 `/api/v1/demo/orders/{order_id}/finish`，再调用 dispatch，枪应回到 `idle`。
12. 调用 `/api/v1/auth/logout` 退出，原 token 再请求应返回401。

步骤8不能只发一条心跳就直接恢复，实际恢复函数要求持续正常采样。
演示不会自动定时发心跳，超过60秒不发送心跳时，需重新完成正常观察再恢复。
`scan-offline`、`dispatch` 是手动触发的模拟任务接口，正式系统应由后台任务调度。
模拟订单只负责占枪/释放及设备命令，不包含计费、支付或结算。

## 自定义约定与正式接入

- 公共安全函数的签名、账号/会话表名和认证接口路径遵循 V1.4。JWT使用HS256，账号连续5次失败锁定15分钟，是本次自定义实现。
- 已兼容种子中的 Argon2id 密码摘要；新演示账号使用带随机盐的 PBKDF2 摘要。正式账号不会被自动重置密码。
- 已兼容旧种子的粗权限：`assets.gun.read` 可用于设备读接口，`assets.pile.manage` 可用于设备写接口。该映射是自定义约定，需要团队确认；角色限制、资源范围仍然执行。
- `Actor.user_id` 在本次设备管理登录中为 `None`；完整车主认证需要再关联对应会员档案。
- 当前场站授权或所属运营商授权都允许访问该场站；仅授权某场站不等于能管理其整个运营商。
- JWT包含随机jti，数据库只存jti摘要。签名正确仍必须存在未撤销、未过期的数据库会话，禁用账号立即失效。角色权限每次从数据库重新加载。
- 原先无条件503阻断已替换。生产入口 `app.main:app` 也注册了认证路由和异常处理，但不会初始化演示数据；需自行配置至少32字符的 `auth_signing_key` 和电话加密密钥。
- Outbox采用至少一次处理，设备适配器必须以 `command_id` 幂等执行，发送超时或进程中断不能保证设备只收到一次命令。当前模拟回执为立即确认；真实异步协议还需用设备回执完成确认。
- 失败重试最多5次，租约60秒，指数退避最多60秒；这些是本次自定义的任务参数。
- SQLite内存库适合单进程学习与隔离验证；MySQL行锁、并发及真实设备网络还未实测。
