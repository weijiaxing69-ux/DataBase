# 第 10 轮审计整改记录

本记录对应《各成员代码问题与未完成功能报告》中成员三的 3 条确定问题和 2 条整合问题。

## 1. 场站功率峰值不能跨时间相加

原实现：窗口内每桩取 `MAX(power_kw)`，再把各桩峰值相加。  
问题：各桩峰值可能出现在不同时刻，相加会高估场站功率，产生误报警。

整改：`list_overloaded_stations()` 改为按“桩 × 分钟”取峰值，再按“场站 × 分钟”求和，最后取场站最严重的分钟。  
新增测试：两桩各 180kW，但峰值出现在不同分钟，任务返回 0 条告警。

## 2. 电压告警必须验证最近连续采样

原实现：窗口内只要有 `samples` 条越限记录就触发，不要求这些记录连续。  
问题：零散异常样本可能被误判为连续越限。

整改：按桩取最近 N 条采样，要求这 N 条全部有输出电流且全部越限，才生成 `VLT01`。  
新增测试：正常/越限/正常/越限的分散样本不触发告警。

## 3. 后台任务补齐周期调度

原实现：只有 `POST /tasks/{name}/run` 手动入口。  
整改：新增 `backend/app/modules/maintenance/scheduler.py`，独立进程运行，按任务间隔调度，使用 MySQL `GET_LOCK` 防多实例重复执行。  
启动方式：

```bash
cd backend
python -m app.modules.maintenance.scheduler
```
