# 第 9 轮迭代：生活场景闭环

## 背景

前 8 轮主要覆盖设备告警、工单闭环、应急事件与部分现场识别。这一轮把日常生活中更容易遇到、但此前没有落到系统里的情况补齐，并给值班人员提供“下一步怎么做”的提示，避免只报码不报处置。

## 新增场景

| 场景 | 生活表现 | 系统处理 |
|---|---|---|
| 长时间充电占位 | 车主充完忘拔枪、慢充过夜占位 | `duration` 任务扫描进行中订单，超过阈值后提醒场站联系车主 |
| 电压越限 | 电网波动、枪头接触不良、整流异常 | `voltage` 任务检查有输出电流的采样，连续越限生成 `VLT01` 告警 |
| 枪状态与订单不一致 | 车主提前拔枪、枪锁卡住 | `gun_mismatch` 任务识别订单与枪状态不一致，提醒人工核实 |
| 故障标记未复位 | 维修后状态没复位，设备看起来可用但有隐患 | `fault_state_mismatch` 任务识别桩/枪故障标记与状态不一致 |
| 充电订单采样断流 | 订单在充但最近没有新采样 | `sampling_gap` 任务识别在线桩的订单采样缺口，提醒核实通信链路 |

## 处置提示

前端告警详情抽屉新增“现场处置提示”，按告警码给出 SOP：

- `CHG01`：核实 BMS/枪头，必要时联系车主重插枪；
- `TEMP01`：检查散热与环境温度，必要时降功率或停机；
- `MET01`：先断电隔离，检查继电器与电表；
- `CAP01`：查看场站功率分布，必要时错峰或限功率；
- `VLT01`：检查电网电压、枪头接触与整流模块；
- `E101`：核实绝缘与接地，必要时停机。

没有专门 SOP 的告警码回落到通用响应流程，保证值班人员始终有下一步动作。

## 设计约束

- 不改动其他成员负责的模块与共享文件；
- 不自动修改枪/桩状态，涉及计费与安全的状态变化仍由人工核实；
- 通知按“设备/订单 + 类型 + 日期”去重，避免重复打扰。

## 验证

新增测试覆盖故障标记未复位与采样断流。维护模块 76 项、全项目 142 项测试通过；前端构建通过。
