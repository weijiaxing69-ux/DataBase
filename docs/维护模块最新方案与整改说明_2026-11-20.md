更新时间：2026-11-20

## 一、当前交付范围

设备监控与故障工单维护模块，覆盖：

- 设备心跳与运行采样
- 告警生成、告警规则、告警恢复
- 工单派单、接单、到场、修复、复核、闭环
- 故障报障与处理

- 应急事件声明、升级、关闭与复盘
- 运维看板、绩效统计、现场处置 SOP
- 周期后台任务与手动触发入口

## 二、本轮重点整改

### 1. 场站功率按同一时间片聚合

旧实现先对每根桩取窗口内峰值，再把各桩峰值相加。  
当不同桩的峰值出现在不同时间时，会高估场站功率并误报警。

新实现：

1. 按“桩 × 分钟”取该分钟峰值；
2. 按“场站 × 分钟”求和；
3. 取每个场站最严重的分钟；
4. 选择该分钟功率最高的桩作为告警载体。

对应代码：`dao.list_overloaded_stations()`。

### 2. 电压越限要求最近连续采样

旧实现只统计窗口内越限记录数量，零散异常样本也会触发告警。

新实现：

1. 按桩取最近 N 条采样；
2. 这 N 条必须全部有输出电流；
3. 这 N 条必须全部低于下限或高于上限；
4. 才生成 `VLT01` 告警。

对应代码：`dao.list_voltage_anomalies()`。

### 3. 后台任务增加周期调度

新增独立调度进程：

```bash
cd backend
python -m app.modules.maintenance.scheduler
```

设计要点：

- 不修改共享 `app/main.py`，降低合并冲突；
- 每个任务有独立执行间隔；
- 使用 MySQL `GET_LOCK` 防止多实例重复执行；
- 单任务失败只记录日志，不阻断其他任务。

当前 16 个任务全部纳入调度：

```text
offline / overdue / recovery / charging / safety / recurring
inspection / temperature / metering / occupied / overload
duration / voltage / gun_mismatch / fault_state_mismatch / sampling_gap
```

## 三、生活场景增量

| 任务 | 生活场景 | 处理方式 |
|---|---|---|
| `duration` | 车主充完忘拔枪、慢充过夜占位 | 超时提醒场站联系车主 |
| `voltage` | 电网波动、枪头接触不良、整流异常 | 最近连续采样越限生成 VLT01 |
| `gun_mismatch` | 车主提前拔枪、枪锁卡住 | 订单与枪状态不一致时提醒人工核实 |
| `fault_state_mismatch` | 维修后故障标记未复位 | 提醒核实，不自动改状态 |
| `sampling_gap` | 订单在充但采样断流 | 提醒检查通信、采样链路和设备状态 |

## 四、现场处置 SOP

前端告警详情按告警码给出处置提示：

- `CHG01`：核实 BMS、枪头与订单状态；
- `TEMP01`：检查散热、环境温度，必要时降功率或停机；
- `MET01`：先断电隔离，检查继电器与计量回路；
- `CAP01`：查看场站功率分布，必要时错峰或限功率；
- `VLT01`：检查电网电压、枪头接触与整流模块；
- `E101`：核实绝缘与接地，必要时停机。

未知告警码回落通用响应流程。
