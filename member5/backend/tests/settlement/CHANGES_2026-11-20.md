# 结算模块补充与验收约定

本轮在 V1.4 原有 30 条接口之外增加三个只读接口，并保留全部原有调用名称。小组合并时应同步代码、迁移及本说明，不能只拷贝测试文件。

## 数据库升级

已有 V1.4 数据库先执行 settlement/10_audit.sql。此迁移只创建审计表，不重建或清空原业务表；可重复执行。新环境仍先装载统一 DDL 与种子，再按顺序安装 05、06、07、10。09_local_grants.sql 仅用于原本地开发账号，应在 10 之后由管理员执行。

审计追加与业务写入使用同一个事务。业务账号仅有审计表 SELECT、INSERT 权限，无 UPDATE、DELETE 权限。记录处理结论的旧值、新值和版本，以及调整申请原因、审批依据、消费发票办理说明、运营商与消费发票红冲原因。历史业务不补造审计事件。

## 扩展接口

| 方法及路径 | 查询和权限 |
| --- | --- |
| GET /api/v1/settlement/adjustments | page、page_size、keyword、settlement_id、status、start_at、end_at；平台、客服和所属运营商可查 |
| GET /api/v1/settlement/adjustments/{adjustment_id} | 检查关联结算单范围；返回申请详情 |
| GET /api/v1/settlement/audit-events | object_type、object_id 必填；支持分页、关键词和时间过滤；先验证对象读取权限 |

object_type 取 settlement、difference、adjustment、operator_invoice、user_invoice。审计结果含 event_id、object_type、object_id、action、actor_id、object_version、before_state、after_state、note、created_at。不存在的对象返回 404，越权返回 403。原有数据无事件时返回空列表。

新增页面 /settlement/adjustments 用于查询待审批和已处理申请，按行审批，无需手填编号。差异、调整、运营商发票及车主发票详情提供操作记录。

## 负余额与零现金

负账单先创建 0 元企业收款事实，并把已有抵扣分配到本账单的正订单；amount 表示结清金额，fleet_credit_amount 表示其中的抵扣，现金分配为两者之差。负余额剩余按来源明细结转一次，原订单必须已经 paid。净额恰为 0 的账单同样通过纯抵扣结清，净额为负的账单保留 issued 供后续结转，结转后 closed。正账单分次收款行为不变。

## 测试命令

安装 Python 测试依赖：python -m pip install -r backend/requirements-test.txt。

标准测试入口：python -m pytest -q backend/tests/settlement。共用夹具会为每项测试创建隔离 MySQL，安装 05、06、07、10；清理后不影响本机开发库。

归档入口：python backend/tests/settlement/run_acceptance.py，将 pytest 输出、JUnit 和汇总写入 results/时间戳。

浏览器测试首次执行 npm --prefix frontend ci 和 npm --prefix frontend exec -- playwright install chromium。然后运行 python backend/tests/settlement/run_browser_tests.py。脚本构建 Vue、启动隔离 MySQL 和 FastAPI、运行真实浏览器写流程并清理测试服务。报告见 frontend/playwright-report，不连接本机 charging_platform。

跨模块联调仍由组内执行：计费退款调用 assert_order_invoice_refundable、apply_fleet_refund_credit；月结到账调用成员二 apply_fleet_bill_payment；专价审批启用接成员二 pricing_review。这里不替代或伪造其他成员的真实实现。
