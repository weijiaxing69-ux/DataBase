# 成员五结算模块 SQL

使用 V1.4 统一建表脚本和已有测试数据 ZIP。成员五的 13 张表由统一脚本创建，历史样例由 ZIP 内的 `04_seed_V1.4.sql` 提供。首次装载历史样例后，再安装本目录的 SQL。历史样例含已开票结算单，按外键顺序写入时确认记录可能晚于发票。

| 顺序 | 文件 | 内容 |
|---|---|---|
| 1 | `05_views.sql` | 运营商结算及开票净额、当前版本差异确认、车队账单与现金实收 |
| 2 | `06_procedures.sql` | 运营商开票与红冲，校验结算净额和原蓝票可冲余额 |
| 3 | `07_triggers.sql` | 蓝票写入前校验当前版本双方确认，写入后将已确认结算单更新为已开票 |
| 4 | `08_queries.sql` | 三道查询各两种写法，第一题连接四个关系 |
| 本机开发账号 | `09_local_grants.sql` | 在已配置原本地专用账号的环境中，追加 V1.4 新接口的表权限 |

所有模块 SQL 使用客户端当前选中的库。按顺序从测试库安装。过程调用须在同一个显式事务内完成，由调用方提交或回滚。FastAPI 服务应在调用前校验权限及资源范围，并通过此过程办理运营商开票和红冲。直接插入发票仍可绕过过程里的累计金额校验。

从项目根目录运行隔离测试：

```powershell
python ".\database\modules\settlement\test_settlement_sql.py"
```

测试复用 V1.4 ZIP 和隔离 MySQL 脚本。验证三张视图、每题两种查询的结果一致，以及仅一方确认、旧版本确认、超额开票、跨结算单红冲和超额红冲等异常。也验证双方确认后开票、红冲后重开和事务回滚。
